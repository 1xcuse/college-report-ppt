# 演讲稿写作指南（speech_script_guide）

配套 `scripts/build_speech.py` 使用。目标：交出一份**可以照着念**的详细讲稿，比 PPT 多出背景、直觉和问答。

- 输入：`content.json`（`references/format_spec.md`）+ `profile.json`（`references/profile_schema.md`）
- 输出：`讲稿.docx`（排版稿）+ `讲稿.md`（可编辑源稿）
- 文案规范：`references/humanizer_cn.md`（说人话规则）；机器检查：`scripts/humanize_lint.py`

---

## 1. 一句话原则

**讲稿是写给耳朵的，不是写给眼睛的。** PPT 上能看懂的，讲稿里不要再念一遍；讲稿要补的是：为什么做、这个词什么意思、这个数字怎么来的、如果被问怎么答。

---

## 2. 时长换算表

中文口播速度按 **220–260 字/分钟**，`build_speech.py` 默认 240。**字**指汉字 + 英文词/数字，不含标点。

| 时长 | 按 220 字/分 | 按 240 字/分 | 按 260 字/分 | 建议页数（含封面/目录） |
|---|---|---|---|---|
| 8 分钟 | 1,760 | 1,920 | 2,080 | 9–12 |
| 10 分钟 | 2,200 | 2,400 | 2,600 | 11–14 |
| 15 分钟 | 3,300 | 3,600 | 3,900 | 13–17 |
| 18 分钟 | 3,960 | 4,320 | 4,680 | 15–19 |
| 20 分钟 | 4,400 | 4,800 | 5,200 | 16–20 |
| 25 分钟 | 5,500 | 6,000 | 6,500 | 18–24 |
| 30 分钟 | 6,600 | 7,200 | 7,800 | 22–28 |

怎么用：

1. 先定总字数区间（如 20 分钟 → 4,400–5,200 字）。
2. 按页型分配：封面/目录每页 100–200 字；方法页、公式页、实验页每页 350–550 字；结论页 250–350 字；致谢 80–150 字。
3. 讲稿正文 ≥ 目标字数下限；超出上限就砍背景举例，别砍结论和数字。
4. 每页留 3–5 秒翻页/看图时间，所以实际口播字数按目标时长的 90% 准备。

`build_speech.py` 会按每页正文的实际字数反推时间分配（字数 ÷ 语速），并在控制台打印「正文 X 字，约 Y 分钟（设定 Z 分钟）」。

## 3. content.json 里的讲稿字段（可选扩展）

`content.json` 契约之外的字段只有 `build_speech.py` 读，`build_deck.py` 会忽略。写法两种：

### 3.1 页面级：每页一段可直接念的讲稿

```json
{
  "type": "bullets",
  "eyebrow": "1.1",
  "title": "低空经济要通感一体",
  "lead": "一个基站，同时供网和盯目标",
  "items": [{"k": "低空经济", "t": "1000 米以下的飞行器活动"}],
  "notes": "低空经济指 1000 米以下的飞行器活动。",
  "speech": {
    "text": "先看背景。……（2–4 段，可直接念）",
    "transition": "下一页看现有方法为什么不够用。",
    "skip": "时间紧可以跳过最后那句「……」。",
    "bg": "本页背景补充：……（可选）"
  }
}
```

- `speech.text`：整段讲稿，优先于 `notes`；写 2–4 个自然段。
- `speech.transition`：口播过渡句；不写时脚本自动生成。
- `speech.skip`：时间紧可跳过哪句；不写时脚本自动挑最后一句。
- `speech.bg`：本页额外背景，追加在讲稿末尾。

### 3.2 全局级：背景、术语、问答、提示

```json
{
  "speech": {
    "greeting": "各位老师、同学下午好。",
    "auto_pages": {
      "cover": "封面页口播（不写则自动生成）",
      "paper_card": "论文简介页口播",
      "toc": "目录页口播"
    },
    "background": [
      {"h": "研究脉络：从固定 UAV 到轨迹优化", "p": "两段背景……"},
      {"h": "关键概念：ISAC 难在哪", "p": "……"}
    ],
    "terms": [
      {"cn": "ISAC", "en": "Integrated Sensing and Communication", "plain": "一套信号同时干通信和雷达两件事。"}
    ],
    "qa": [
      {"q": "为什么不直接加权成单目标？", "a": "加权和只能给一个折中点，换权重就得重训。", "scope": "组会"}
    ],
    "tips": [
      {"h": "本场特别提醒", "p": "投影是 4:3，图别放太靠右。"}
    ]
  }
}
```

不给这些字段也能生成：脚本会用 `notes` + 页面要点/表格/图注/`paper` 自动拼一份草稿。但自动稿只有目标字数的 30%–60%（12 页的组会稿约 1,300–1,800 字），只适合应急；正式汇报建议每页都写 `speech.text`，背景至少 4 节。

两个约定：

- `paper.venue` 是 format_spec v2 的期刊字段；脚本同时兼容旧写法 `paper.journal`，有 `venue` 时优先用 `venue`。
- 页面有 `speech.text` 时整段使用，**不会再和 `notes` 拼接**；`notes` 只作为没有 `speech.text` 时的扩写底稿。

## 4. docx 结构（build_speech 生成）

| 顺序 | 内容 | 说明 |
|---|---|---|
| 封面 | 题目 / 学校 / 学院 / 汇报人 / 身份 / 目的 / 对象 / 日期 / 时长 / 字数 | 从 profile 与 paper 取 |
| 一、时间分配表 | 部分 / 页码 / 预计用时 + 合计 | 按页数、正文长度、时长自动算 |
| 二、逐页讲稿 | 「第 N 页　标题（用时）」+ 正文 + 〔过渡〕+ 〔时间紧可跳过〕 | 覆盖封面、论文简介、目录、每页正文 |
| 三、论文背景补充 | 研究脉络 / 关键概念 / 方法直觉 / 实验细节 / 相邻工作 | PPT 里没有的背景 |
| 四、术语表 | 术语 / 英文 / 一句白话解释 | 中英对照 |
| 五、预设问答 | 8–12 条，标注〔组会〕〔课程〕〔答辩〕 | 按 purpose 调整侧重 |
| 六、口头表达提示 | 开场、看图表、讲公式、控场、收尾 | 通用 + 目的专属 |

排版：A4、宋体正文（12 pt，1.5 倍行距，首行缩进 2 字符）、黑体标题、三线表、页眉页脚页码。字体和字号可改：`--body-font` / `--title-font` / `--body-size` / `--line-spacing` / `--accent`。

自动生成规则：

- 过渡句按下一页页型（章节页 / 要点页 / 图页 / 表格页 / 结论页 / 致谢）从 40 多条句库里挑，**全篇不重复**；写了 `speech.transition` 就用作者的。
- `〔时间紧可跳过〕`不逐页刷屏：每 4 页最多 1 条，优先挑有 `speech.skip` 的页；没标的页面本身不长，不用跳。自定义的 skip 文案不要再写「时间紧可以跳过」前缀，脚本会加标签。
- 各页用时按该页正文的实际字数比例分配，不是平均分；总量对不齐设定时长时，控制台和 docx 里都会给醒目提示。

命令：

```bash
PY="${DSH_PYTHON:-$(command -v python3)}"   # DSH 自带 Python 也可，见 SKILL.md 的解释器探测
$PY scripts/build_speech.py --content content.json --profile profile.json \
    --out 讲稿.docx --md 讲稿.md --pptx 汇报.pptx
```

`--pptx` 可选，用来核对 PPT 页数和备注字数；没装 python-pptx 时只提示、不报错。

## 5. 每页讲稿怎么扩写（不是复述 PPT）

一页 PPT 的 `notes` 通常只有 1–3 句（≤120 字）。扩写成 300–500 字讲稿，用下面 5 个动作：

1. **补来路**：这个概念/方法是谁先提的、属于哪条线（只写论文里有的）。
2. **补概念**：术语第一次出现，加一句「通俗地说」。
3. **补直觉**：作者为什么这么设计？不用公式，用一句话说清取舍。
4. **补数字**：PPT 上的结论后面接一个具体数字和单位。
5. **补判断**：自己对这篇工作的评价（好在哪、局限在哪），用「我」开头。

扩写示例（notes → 讲稿）：

> notes：传统优化解这个非凸问题，迭代很多还常是次优；DQN 只能出离散动作，连续量离散化维度会爆；DDPG 能出连续动作，但只学一个目标，b 一换就要重训。
>
> 讲稿：
> 那现成的方法能不能直接用？分开看。
> 传统凸优化：这个问题本身非凸，波束和轨迹又强耦合，迭代次数多，结果经常停在次优点。
> DQN：只能从离散动作里挑。波束矩阵和轨迹都是连续量，离散化以后维度会爆炸。
> DDPG：能直接输出连续动作，但它一次只学一个目标。偏好权重 b 一换，就得重训一遍。
> 三种方法各缺一块。所以这篇论文要同时解决两件事：连续动作，和多目标共享训练。

不要做的事：

- 不要照着 PPT 标题念（「这一页讲研究背景」）。
- 不要念公式符号（「这里 W_c 是……W_s 是……」）。
- 不要用论文摘要腔（「本文提出」「综上所述」）。
- 不要编论文没写的数字（讲稿里写「论文没有写」，反而加分）。

## 6. 过渡句库（≥20 条）

过渡句的作用：告诉听众「刚才那段结束了、接下来是什么关系」。每页一句，不重复。

### 6.1 进入下一页/下一部分

1. 接着往下看。
2. 下一页是……
3. 把刚才的说法往下推一步。
4. 说到这，下一页正好是……
5. 先记住这个结论，下一页解释它怎么来的。
6. 这部分讲完，下面进入……
7. 下面换个角度。
8. 先看结论，再看它是怎么做到的。

### 6.2 背景 → 方法

9. 那现成的方法能不能直接用？
10. 前人卡在哪，决定了这篇论文要做什么。
11. 问题清楚了，下面看作者怎么建模。
12. 建模之前，先把场景摆出来。

### 6.3 方法 → 实验

13. 方法讲完了，能不能work，看实验。
14. 理论上的设计，实验里到底有没有用？下面看数据。
15. 先交代实验条件，再看结果。

### 6.4 实验内部（图 → 图）

16. 这张图看收敛，下一张图看泛化。
17. 换一个角度：如果偏好权重变了呢？
18. 只看平均指标不够，下面把四个变体拆开对。
19. 数字看完，最后看飞行轨迹长什么样。

### 6.5 收束 / 结论

20. 讲到这里可以下结论了。
21. 最后收一下，说三条结论和两点不足。
22. 这篇论文给我们能接的地方，也就这两个。

### 6.6 应对提问 / 控场

23. 这个问题很关键，我分两点答。
24. 具体数字我记不太准，会后查了发群里。
25. 这块论文没有展开，我说说我的理解。
26. 时间关系，这一页我快速过，会后可以细聊。

使用注意：同一句过渡句全篇最多用一次；过渡句不承载新信息，别把结论塞进去。

## 7. 怎么口头解释图

顺序固定：**这张图在比什么 → 横轴纵轴和单位 → 趋势 → 一个具体数字 → 结论**。

句式模板：

- 「这张图横轴是训练回合，纵轴是和速率，单位是 bps/Hz。」
- 「先看形状：MODE 上升最陡，一万回合左右到平台。」
- 「具体数字：平台在 2.1×10² bps/Hz。」
- 「MODE-w 起点低一点，两万回合追平，所以最后两条线基本重合。」
- 「这一页要记住的是：MODE 赢在收敛速度，不在最终指标。」

按图型：

| 图型 | 先说什么 | 不要做 |
|---|---|---|
| 曲线图 | 横纵轴、单位、几条线分别是谁、趋势、平台值 | 从图例第一条开始念 |
| 柱状图 | 分组是什么、柱子高低顺序、差距百分比 | 逐根念数值 |
| 框架图 | 从左到右/从上到下走一遍数据流，只讲 3 个关键模块 | 每个小方块都讲 |
| 表格 | 表头是什么、挑 3 个关键行 | 逐行念 |
| 轨迹图 | 坐标平面、起点终点、绕开了什么 | 描述每个点 |
| 公式 | 先讲在算什么、再点 2 个符号 | 从头念符号 |

常见错误：

- 图注里写了「(a)(b)」，讲的时候说「左图/右图」，别说「图 2.6(a)」。
- 纵轴有 ×10²、×10⁻² 一定要先说明，否则听众会把 0.9 听成 0.9 而不是 90。
- 先给结论再给过程，别让听众自己找重点。

## 8. 怎么口头解释公式

四步法，每步一句话：

1. **它在算什么**：「这个公式在算两个目标的期望值，一个是通信和速率，一个是感知 SNR。」
2. **变量分几组**：「变量分两组：两组波束矩阵，和 K 条飞行轨迹。」
3. **约束卡在哪**：「五条约束：飞行距离、起终点、两类防碰撞、总功率上限。」
4. **为什么难**：「非凸、强耦合、目标还会随机跑，所以传统优化不好做。」

示例（可直接用）：

> 公式不用一个一个符号念。这张图只有一件事：问题被写成「两个目标一起最大化」，不是先加权成一个数。目标函数是向量，期望要对目标的随机机动取。约束是 6b 到 6f 五条，6a 是目标函数，不是约束。难点三个：非凸、波束和轨迹强耦合、目标的机动基站不知道，所以期望没法解析算。

注意：

- 板书/PPT 上的公式编号要念对（「公式 6a」），不要念错编号。
- 论文原稿写错的地方（例如「六个约束」其实是五条）可以在讲稿里说明，这是加分项。
- 不要展开推导，除非评委追问；推导放到「背景补充」或问答里。

## 9. 组会 / 课程 / 答辩：三种语气

| 维度 | 组会文献汇报 | 课程汇报 | 答辩 |
|---|---|---|---|
| 听众 | 同门、导师 | 老师、同学 | 答辩委员会 |
| 默认时长 | 18–25 min | 8–10 min | 20–30 min |
| 重点 | 方法 + 实验 + 自己的判断 | 背景 + 概念 + 有没有读懂 | 创新点 + 证据 + 工作量 |
| 背景占比 | 20%–30% | 40%–50% | 15%–20% |
| 人称 | 「我」「我们课题组」 | 「我们」「大家」 | 「本文」「我的工作」 |
| 术语 | 可以直接用 | 第一次出现要解释 | 可以直接用，但要准确 |
| 数字要求 | 关键结果给数字 | 概念配例子 | 每个结论都要数字支撑 |
| 风险 | 被问「这篇和你的方向什么关系」 | 被问基础概念 | 被追问创新点和对比公平性 |
| 收尾 | 讲局限和可接的点 | 讲收获和反思 | 讲贡献、不足、展望 |

同一句话的三种说法：

- 组会：「MODE 和 MODE-w 最后基本重合，所以 MoE 的价值不在单任务指标，在换 b 的时候省重训。」
- 课程：「这里可以理解成：多个偏好权重共用一套底层网络，换权重时只换最后一层。」
- 答辩：「在两项指标上 MODE 与消融版并列最高；MODE 的贡献是跨偏好权重的泛化能力，代价是多一个门控和若干专家。」

答辩特别注意：

- 创新点用一句话说完，最多三点，每点后面立刻跟证据。
- 被质疑对比不公平时，先说设置（同一个仿真、同样的训练回合），再说结论边界。
- 不会的题别硬答：「这块我没细看，记下来会后查」比编造安全。

## 10. 常见问答模式（8 类）

准备问答时按这 8 类各写 1–2 条，覆盖 80% 的现场问题。

| 类型 | 典型问法 | 回答结构 |
|---|---|---|
| 动机类 | 为什么做这个？为什么选这篇论文？ | 场景痛点 → 现有方法缺什么 → 这篇补什么 |
| 方法类 | 为什么用 MoE / 为什么不用 PPO？ | 问题特征（连续/多任务）→ 方法匹配 → 代价 |
| 指标类 | 为什么只测 SNR？为什么用和速率？ | 指标定义 → 为什么选它 → 它测不出的东西 |
| 数字类 | 这个 40% 怎么算的？和谁比？ | 基线是谁 → 同一设置 → 具体数值 |
| 公平性 | 对比公平吗？训练回合一样吗？ | 设置对齐 → 差异说明 → 结论边界 |
| 局限类 | 有什么不足？能用到真实场景吗？ | 论文自己列的不足 → 我的判断 → 下一步 |
| 扩展类 | 能推广到多基站 / 其他频段吗？ | 依赖的假设 → 哪些能直接搬 → 哪些要重做 |
| 基础类 | 这个术语什么意思 / 公式怎么推的？ | 一句白话 → 关键假设 → 完整推导在论文第几页 |

回答模板（30 秒以内）：

> 「这个问题分两层。第一层是……（结论）。第二层是……（原因/数字）。论文里对应第 X 页，会后我可以把细节发群里。」

问答准备的三个技巧：

1. 每个答案先写「一句话结论」，再写「支撑数字」，最后写「边界（什么情况下不成立）」。
2. 预判最狠的一个问题，提前写 100 字答案并念熟。
3. 准备一句万能兜底：「这块我没细看，记下来会后查。」

## 11. 讲稿写作流程（agent 照做）

1. 读 `content.json`，确认 `purpose`、`duration_min`、页数、每页 `notes`。
2. 算目标字数（见第 2 节），分配到页。
3. 逐页写 `speech.text`：
   - 第一段：承接上页 + 本页结论；
   - 第二段：解释 why / how，补背景或数字；
   - 第三段（可选）：自己的判断或提醒。
4. 写 `speech.background` 4–6 节（研究脉络、关键概念、方法直觉、实验细节、相邻工作）。
5. 写 `speech.terms` 8–12 条（中英 + 白话）。
6. 写 `speech.qa` 8–12 条（按组会/课程/答辩标注）。
7. 跑 `build_speech.py`，看字数/时长/问答数是否达标。
8. 跑 `humanize_lint.py --content` 和 `--text 讲稿.md`，high 清零。
9. 自己念一遍；念不顺的地方改到顺为止。

## 12. 交付前检查

- [ ] 正文总字数在目标时长 ±15% 内（20 分钟 → 4,100–5,500 字）。
- [ ] 每页讲稿 ≥ 250 字（封面/目录/致谢除外），没有一页只有一句。
- [ ] 每页都有过渡句；全篇过渡句不重复。
- [ ] 每页都有「时间紧可跳过」的句子，且跳过的不含关键数字。
- [ ] 背景补充 ≥ 4 节，术语 ≥ 8 条，问答 8–12 条。
- [ ] `humanize_lint --strict` 无 high；讲稿没有「本文提出/综上所述/值得注意的是」。
- [ ] 数字、单位、术语和 `content.json` 完全一致。
- [ ] docx 能被 Word 打开，页码、表格、字体正常（用 `python-docx` 回读检查段落数/字数/标题结构）。
