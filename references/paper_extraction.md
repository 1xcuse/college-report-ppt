# 论文提炼方法论（paper → content.json v2）

给 agent 用的操作手册：怎么把一篇论文提炼成**准、短、分条列点、可回溯**的中文学术汇报内容。
配套脚本（同目录 `scripts/`）：

| 步骤 | 脚本 | 产物 |
|---|---|---|
| ① 抽素材 | `paper_extract.py` | `paper.md`（带页标记正文）+ `paper_card.json` + `layout.json` |
| ② 抽图 | `extract_figures.py` | `figures/figNN.png` + `figures.json`（可选 `--split-panels` 出 `fig03a.png` 等） |
| ③ 回查 | `verify_claims.py` | 按页的问题报告（数字/术语/字段/长度/图注/空标题） |

**铁律：先有 `paper.md` 再写 content.json；写完 content.json 必须跑 `verify_claims.py --strict`，通过才交给 `build_deck.py`。**

```bash
PY=/opt/anaconda3/bin/python3   # 带 PyMuPDF/Pillow
$PY scripts/paper_extract.py --pdf x.pdf --out work/a/paper
$PY scripts/extract_figures.py --pdf x.pdf --out work/a/figures --split-panels
$PY scripts/verify_claims.py --content content.json --paper work/a/paper/paper.md \
    --figures work/a/figures/figures.json --strict
```

## 一、三遍法

不要一上来就写 PPT。三遍各有明确产出，跳步必错。

### 第一遍：读结构（5–8 分钟，产出 paper_card）

目标是**知道这篇论文的骨架**，不抠细节。看这些地方：

1. **题名 + 摘要 + Index Terms**：一句话说清「研究对象 + 方法 + 结果」。
2. **贡献列表**（Introduction 末尾 `1) 2) 3)` 或 Contributions 段）：这通常就是后面每一页的骨干。
3. **章节标题**（`paper_card.json.sections`）：一级标题定目录，二级标题定每页标题的素材。
4. **图表清单**（`paper_card.json.figures/tables`）：图 1 通常是场景/问题，图 2 是框架，后面是结果。
5. **期刊信息**（`paper_card.json` 的 journal/volume/doi/year）与**页数**。

产出 `paper_card.json` 里能直接用进 content.json 的字段：

```json
"paper": {
  "title_cn": "…", "title_en": "论文原题（照抄，不改写）",
  "authors": "英文作者名，按论文首页",
  "affiliations": "单位（paper_card.json 的 affiliations，可中文重写但单位名不编）",
  "keywords": "从 Index Terms 译写",
  "summary": "一句话说清做了什么（≤48 字）",
  "journal": "…", "volume": "…", "doi": "…",
  "ranks": ["CCF A 类（计算机网络）"],
  "metrics": "影响因子 8.8（2025 JCR）",
  "source_note": "数据来源：LetPub / 期刊官网（查询日期 2026-11）",
  "contributions": [{"k": "多目标 MDP", "t": "…"}],
  "limits": [{"k": "单基站", "t": "…"}],
  "figures": [{"file": "fig01.png", "caption": "…", "page": 4, "kind": "scene"}]
}
```

> **分区/影响因子必须现查**：用 `--source-doc` 把 LetPub / 期刊官网的本地记录传给 `verify_claims.py`。
> 查不到就整项省略，不猜、不估。

### 第二遍：抓骨架（15–25 分钟，产出「每节 2–4 条可讲事实」）

对每个一级章节问三个问题：

1. 这节**解决什么问题**（动机/难点）？
2. 这节**用了什么招**（模型/算法/机制，最多 3 块）？
3. 这节**拿什么证明**（图几、表几、关键数字）？

把答案写成一张草稿表，每节 2–4 条，一条一个事实来源：

| 章节 | 要讲的事实（每条带页码） | 配图 |
|---|---|---|
| 引言 | ①低空经济指 1000 m 以下（p1）②一个 GBS 同时供网+感知（p1） | Fig.1 |
| 系统模型 | ①N 天线、K 架授权无人机、1 个目标（p4）②5 条约束（p5） | Fig.1/2 |
| 方法 | ①多任务 MoE：1 个门控+M 专家+L 输出层（p7）②整回合回放（p9）③约束动作选择（p10） | Fig.2 |
| 实验 | ①K=6、N=8、T=40、60 m（p11）②MODE 收敛快 68.81%（p12） | Fig.3/4/7 |

**抓手顺序**：`paper.md` 里搜以下锚点，比通读快得多：

- `contributions` / `1)` / `2)` / `3)`：贡献
- `Fig.` / `TABLE`：图表锚点
- `= 6` / `= 40` 这类参数赋值：实验设置
- `%` / `bps` / `dB` / `ms`：结果数字
- `limitation` / `future work` / `we only`：不足与展望

### 第三遍：回查（每页 1–2 分钟，产出可交付 content.json）

逐页把要写的**每个数字、单位、英文术语**回到 `paper.md` 里核对一遍（ctrl-f 或用 `verify_claims.py`）：

- 数字必须逐位一致（8.8 就是 8.8，不是 8.80 也不是约 9）。
- 百分比注意单位与口径（「提高 18.82%」还是「提高 18.82 个百分点」）。
- 英文缩写保留原文大小写与连字符（`MODE-w`、`Gauss-Markov`、`bps/Hz`）。
- 论文没给的参数，写「论文没有写」，**不要替作者补**。
- 图注里的图号用论文原图号（论文是 `Fig. 3(a)` 就写「图 3（a）」，不要重排成「图 2.6（a）」）。

`verify_claims.py` 会把问题按页列出来，每条带「候选证据原文片段」——照着原文改，不要绕过检查。

## 二、页面提炼规则（与 `format_spec.md` 对齐）

### 2.1 页数与节奏

- 15 分钟组会汇报：12–18 页正文（不含自动页），每页 45–90 秒。
- 20 分钟：16–22 页。
- 一页只讲一件事；宁可页数多，不要一页塞 6 条。

### 2.2 标题：结论化，≤22 字

标题是这页的结论，不是这页的栏目名。

| ❌ 空泛 | ✅ 结论化 |
|---|---|
| 研究背景 | 低空经济要靠通感一体 |
| 系统模型 | 一个基站同时供网与盯目标 |
| 现有方法 | 现成方法各缺一块 |
| 实验结果 | 收敛快 68.81%，但单任务指标没赢 |

`verify_claims.py` 会把「研究背景 / 方法 / 实验 / 结论」这类标题判为**提示**（不拦），但看到提示就该改。

### 2.3 分条列点：每页 3–4 条，k ≤10 字、t ≤46 字

- `items[].k`：核心词，加粗，10 字以内（「传统优化」「多任务 MoE」「整回合回放」）。
- `items[].t`：一句话说明，46 字以内，**一个事实一条**，不写长段落。
- `lead`（可选）：整页一句话结论，≤40 字，放高亮条。
- 3–5 条是甜点区；超过 5 条就拆页。

### 2.4 配图：正文页 2–4 张核心图

从 `figures.json` 选，优先级：

1. `kind: scene`（场景图）——讲背景/系统模型时用，通常 Fig.1；
2. `kind: framework`（框架图）——讲方法总览时用，通常 Fig.2；
3. `kind: result`（结果图）——讲实验时用，每讲一个结论配一张；
4. `kind: table`（表格截图）——实验设置/对比，能用三线表重画就重画，别贴截图。

图片规则：

- 图注 ≤36 字，只写「图是什么」，不下结论；结论放 `lines`/`items`。
- 纵向堆叠的 (a)(b) 子图用 `extract_figures.py --split-panels` 拆成 `fig03a.png` / `fig03b.png`，
  单张接近正方/横向，方便 16:9 排版。
- 一张图只在第一次出现时写 `source` 脚注。

### 2.5 公式：只留 1–2 个关键的

- 全篇公式页 ≤2 页；每页最多 2 个公式（+ 一句人话解释）。
- 优先选：问题建模的目标函数与关键约束（如 (6a)–(6f)）、核心机制的一句话公式。
- 推导过程、中间变量定义一律不进 PPT，放讲稿。

### 2.6 对比表：全篇 1 张

- 实验设置表（参数 + 取值）或方法对比表（传统方法 vs 本文），二选一，不要两张都上。
- 表格单元格 ≤24 字；论文没给的参数写「论文没有写」放在 `tnote`。

### 2.7 每节 1 个 keynums 或 quote

- `keynums`（2–4 个数字）：一页让人记住的关键量（40 时隙 / 8 天线 / 6 无人机 / 5 万回合）。
- `quote`：全篇最多 1 页，放作者的核心直觉或一句能记住的话。

## 三、按论文类型取舍

### 3.1 系统 / 方法类（本文示范：MODE）

重心在「怎么做」，页数配比约 背景 20% / 方法 50% / 实验 25% / 结论 5%。

- 必须讲清三件事：**场景 → 问题建模（目标+约束）→ 方法的三块设计**。
- 方法块每块一页：一页讲「为什么加这块、这块长什么样、代价是什么」。
- 实验页按「一个结论一张图」组织：收敛、跨参数、消融/对比，各一页。
- 不足与展望直接从 Conclusion 最后一两句抓（`single-GBS`、`detection probability`、`CRB`）。

### 3.2 综述类（示范：COMST 那篇 ISCC survey）

重心在「地图」，页数配比约 引言 10% / 分类框架 40% / 代表性方法 35% / 趋势与挑战 15%。

- 先讲清楚**分类维度**（按什么切分），再用这个维度把文献归类。
- 每页只讲 1 个类别，配 1 张分类表或框架图；不要逐篇罗列作者。
- 数字少、概念多 → 多写 `text`/`compare` 页，少用 `keynums`。
- 综述的「不足」通常是开放问题（open problems），照抄作者的 open problems 标题即可。

### 3.3 实验 / 基准类（示范：TCOMM 信道估计）

重心在「怎么比、比出什么」，页数配比约 问题 20% / 方法与实验设计 35% / 结果 35% / 结论 10%。

- 实验设置必须一页表格（数据集、基线、指标、超参）；缺的写「论文没有写」。
- 结果按「指标 × 对比对象」组织；主结果 1 页，消融 1 页，鲁棒性 1 页。
- 注意纵轴单位与倍数（如 `1e2`、`×10²` 标度），图注里写清楚，别念错数量级。
- 不要只说「本文最好」：说清好在哪（精度/速度/参数量/低 SNR 段）。

## 四、禁区（verify_claims.py 会拦的）

1. **不编数据**：论文没有的数字不写；确实需要说明时写「论文没有写」。
2. **不补参数**：论文没给 Δt、P_max、M、L 就写「论文没有写」，不要从常识推。
3. **不猜期刊分区/影响因子**：必须现查并写 `source_note`，查不到就省略。
4. **不把作者没说的结论写成作者的**：因果、优越性、普适性只在论文明确写了的地方说。
5. **不自己重编图号**：用论文原图号；子图写（a）（b）。
6. **不把「代码开源」「数据公开」写进去**，除非论文明确写了。
7. **不把综述里的他人结论算成本文贡献**。

### 5.3 这篇论文的讲稿口播（每节一句，放 builds_speech 底稿）

- 背景：低空经济是 1000 米以下的飞行器活动，一个基站要同时供网和看目标。
- 缺口：现成方法要么慢要么只能单目标，论文要的是连续控制加多目标共享。
- 方法：多目标 MDP + 多任务 MoE + 整回合回放，三块各解决一个问题。
- 结果：收敛快 68.81%，跨偏好权重不用重训；单任务指标与简化版 MODE-w 基本并列。
- 不足：只做单基站，感知只有 SNR，检测概率和 CRB 留给下一步。

### 5.4 这篇论文的验收记录

- `paper_extract`：17 页标记、6 个一级章节、17 个二级章节、8 张图注、3 张表注、67 条参考文献。
- `extract_figures`：8 张整图 + `--split-panels` 额外 6 张子图（fig03a/b、fig05a/b、fig07a/b），均 ≥600px 宽。
- `verify_claims`：content.json 34 条数字断言全部命中（100%）、24 个英文术语全部命中（100%），0 错误。
- 变异测试：影响因子 8.8→9.9 被定位到第 2 页（论文简介）；训练回合 50,000→80,000 被定位到表格页并给出原文候选「50,000」。
